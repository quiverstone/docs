title: "Inventory Roles"

---

Inventory roles provide read-only access to AWS Organizations, enabling Quiverstone to automatically discover accounts in your organization. Deploy these roles to enable organization-level account discovery and monitoring.

## When to Use Inventory Roles

- Automatically discover all accounts in your AWS Organization
- Monitor organization structure and account changes
- Enable organization-wide account management in Quiverstone
- Provide read-only access to AWS Organizations API
- Deploy from management account or delegated administrator account

<Note>
**Your External ID comes from Quiverstone.** Quiverstone generates one External ID for your workspace and shows it on the **Add Organization** screen. Always use that value where a template asks for your Quiverstone External ID — do not make up your own. Quiverstone presents it every time it assumes a direct role or your intermediate role.
</Note>

Inventory roles are always assumed by Quiverstone itself, so they come in two variants: **direct** and **chained**. (Browser-session roles are an access-role option only — see [Access Roles](/setup/accounts/access).)

## Deploy from AWS CloudShell (fastest)

Every inventory role can be deployed with one command from [AWS CloudShell](https://console.aws.amazon.com/cloudshell/home). Quiverstone generates the command for you with your External ID filled in: on **Add Organization**, choose **Quick Setup**, or open the **Deploy with AWS CloudShell** panel in Advanced mode.

The command downloads the Quiverstone onboarding script and runs it. The script checks that you are signed in to the right account, deploys a single CloudFormation stack, and prints the role ARN.

```bash
curl -fsSL https://s3.us-east-2.amazonaws.com/assets.quiverstone.io/role-catalog/scripts/quiverstone-onboard.sh -o quiverstone-onboard.sh && bash quiverstone-onboard.sh --role-type org-inventory --variant direct --external-id <your-quiverstone-external-id> --role-name QuiverstoneInventory --region us-east-1
```

| Role | Run in | Key flags |
|---|---|---|
| Direct org inventory | Management account | `--role-type org-inventory --variant direct --external-id <id>` |
| Delegated administrator | Delegated admin account | add `--account-type delegated-admin` |
| Trusted intermediate (chained, step 1) | Your intermediate account | `--role-type intermediate --external-id <id> --assume-scope specific-role-any-account --destination-role-name QuiverstoneInventory` |
| Chained org inventory (step 2) | Management account | `--role-type org-inventory --variant chained --intermediate-role-arn <arn>` |
| Standalone account inventory | The standalone account | `--role-type standalone-inventory --external-id <id>` |

<Note>
The CloudShell region doesn't matter: IAM roles are global, and the stack is created in the region you pass with `--region` (default `us-east-1`). If a download fails, the command stops and names the URL it could not fetch.
</Note>

## Direct Inventory Deployment

Direct inventory access is the most common deployment method where Quiverstone directly assumes the inventory role in your organization's management or delegated administrator account.

<Steps>
  <Step title="Launch CloudFormation Template">
    Click the button below to launch the direct organization inventory role template in your management or delegated administrator account:

    [![Launch Stack](/assets/stack.png)](https://console.aws.amazon.com/cloudformation/home?region=us-east-1#/stacks/quickcreate?templateURL=https://s3.us-east-2.amazonaws.com/assets.quiverstone.io/role-catalog/inventory/direct-org-inventory-role.yaml&stackName=quiverstone-direct-org-inventory-role)
  </Step>

  <Step title="Configure Essential Parameters">
    **Target Role Name** (`pRoleName`): Name for the inventory role (Default: QuiverstoneInventory)

    <Warning>
    **Security Best Practice**: Change the default role name to a custom value unique to your organization. Using default role names makes it easier for unauthorized parties to discover and potentially target your roles.
    </Warning>

    **Account Type** (`pAccountType`): `MANAGEMENT` (default) or `DELEGATED_ADMIN`. Delegated admin omits management-only APIs.

    **External ID** (`pExternalId`): **Required.** Paste your Quiverstone External ID from the Add Organization screen.
  </Step>

  <Step title="Create Stack">
    Review the parameters and create the CloudFormation stack. Wait for the stack to reach CREATE_COMPLETE status.
  </Step>

  <Step title="Copy Role ARN">
    From the stack Outputs tab, copy `oTargetRoleArn` (e.g., `arn:aws:iam::123456789012:role/QuiverstoneInventory`)
  </Step>

  <Step title="Configure Quiverstone">
    In Quiverstone, add the organization with the Role ARN from the previous step. Your External ID is applied automatically.
  </Step>
</Steps>

<Note>
The inventory role only provides read-only access to AWS Organizations. It cannot make changes to your organization structure or account settings. For detailed deployment information, see the [Inventory Roles Reference](/setup/iam-roles/inventory).
</Note>

## Chained Inventory Deployment

Chained inventory access adds an intermediate security layer by routing role assumptions through a trusted account you control. Use this when security policies require additional controls beyond direct access to your management account.

<Warning>
Chained inventory requires two deployments: first the intermediate role, then the destination inventory role. Deploy in this order.
</Warning>

<Steps>
  <Step title="Deploy Intermediate Role (First)">
    Deploy the intermediate role to your trusted/intermediate account:

    [![Launch Stack](/assets/stack.png)](https://console.aws.amazon.com/cloudformation/home?region=us-east-1#/stacks/quickcreate?templateURL=https://s3.us-east-2.amazonaws.com/assets.quiverstone.io/role-catalog/intermediate/trusted-intermediate-role.yaml&stackName=quiverstone-trusted-intermediate-role)

    **Essential Parameters:**
    - **Role Name** (`pIntermediateRoleName`): Default is QuiverstoneTrustedIntermediate
      <Warning>Change this to a custom role name for enhanced security</Warning>
    - **External ID** (`pExternalId`): **Required.** Your Quiverstone External ID — Quiverstone presents it on this first hop.
    - **Assume Role Scope** (`pAssumeRoleScope`): Use `specific-role-any-account` (recommended)
    - **Destination Role Name** (`pDestinationRoleName`): The inventory role name you will use in Step 2 (e.g. QuiverstoneChainedOrgInventory)
      <Warning>Change this to match your custom destination role name</Warning>

    <Note>
    If you already have an intermediate role deployed, you can reuse it. Skip to Step 2.
    </Note>

    Copy the intermediate role ARN (`oIntermediateRoleArn`) from the stack outputs.
  </Step>

  <Step title="Deploy Chained Inventory Role (Second)">
    Deploy the chained inventory role to your management or delegated administrator account:

    [![Launch Stack](/assets/stack.png)](https://console.aws.amazon.com/cloudformation/home?region=us-east-1#/stacks/quickcreate?templateURL=https://s3.us-east-2.amazonaws.com/assets.quiverstone.io/role-catalog/inventory/chained-org-inventory-role.yaml&stackName=quiverstone-chained-org-inventory-role)

    **Essential Parameters:**
    - **Inventory Role Name** (`pInventoryRoleName`): Default is QuiverstoneChainedOrgInventory
      <Warning>Change this to a custom role name for enhanced security</Warning>
    - **External ID** (`pExternalId`): Optional hop-2 External ID (highly recommended). If you set one, enter the same value as the destination External ID in Quiverstone. Your Quiverstone External ID is already enforced on the intermediate role.
    - **Intermediate Account ID** (`pIntermediateAccountId`): Account ID where intermediate role is deployed
    - **Intermediate Role Name** (`pIntermediateRoleName`): Name of intermediate role (default: QuiverstoneTrustedIntermediate)
      <Warning>Update this if you changed the intermediate role name</Warning>
    - **Trust Scope** (`pTrustPrincipals`): Use `Named` for enhanced security (recommended)

    Copy the chained inventory role ARN (`oTargetRoleArn`) from the stack outputs.
  </Step>

  <Step title="Configure Quiverstone">
    In Quiverstone, configure chained inventory access using:
    - Intermediate role ARN (from Step 1) — your Quiverstone External ID is applied to it automatically
    - Destination role ARN (from Step 2), plus its hop-2 External ID if you set one
  </Step>
</Steps>

<Note>
For detailed deployment information, see the [Inventory Roles Reference](/setup/iam-roles/inventory).
</Note>

## Standalone Account Inventory

For AWS accounts that are not part of an organization, you can deploy a standalone account inventory role (`pRoleName` default QuiverstoneStandaloneAccountInventory, `pExternalId` required). This provides basic account information without organization-level discovery.

For detailed information about standalone account inventory deployment, see the [Inventory Roles Reference](/setup/iam-roles/inventory).
